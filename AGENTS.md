# AGENTS.md

## Рабочий язык

Рабочий язык проекта — русский. Код, имена файлов, API-поля и технические идентификаторы сохраняются в исходном формате, если задача не требует иного.

## Source of truth

При противоречии источников используй следующий порядок приоритета:

1. `_docs/specs.md`
2. Будущий API contract
3. Tests
4. Implementation

## Перед реализацией

- Изучи текущую архитектуру, инструкции проекта, состояние репозитория и релевантные файлы.
- Проверь соответствие планируемого изменения `_docs/specs.md`, будущему API contract и существующим tests.
- Если требования, API contract или tests противоречат друг другу, не делай предположений: зафиксируй расхождение и запроси решение.
- Не добавляй технологические решения до их явного выбора в проекте.

## Scope

- Реализуй только MVP из `_docs/specs.md`.
- Не расширяй scope за пределы MVP и его acceptance criteria без явного согласования.
- Non-Goals из `_docs/specs.md` не входят в реализацию.
- Предпочитай минимальное корректное изменение широкому рефакторингу.

## Quality

- Для важных изменений следуй циклу: inspect → plan → implement → verify → document.
- Не считай задачу завершённой только после изменения кода: выполни доступные релевантные проверки.
- Отделяй подтверждённые факты, выводы и предположения.
