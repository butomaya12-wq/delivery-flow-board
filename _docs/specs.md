# Delivery Flow Board — Product Specification

## Problem

Заказами на доставку сложно управлять, если их текущие статусы хранятся в списках, таблицах или сообщениях. Оператору нужен простой способ быстро видеть, какие заказы только поступили, какие готовятся, какие уже переданы в доставку, а какие завершены.

## User

Основной пользователь системы — оператор или менеджер доставки, который контролирует заказы и обновляет их статусы.

## Goal

Создать простой Kanban board, который позволит оператору видеть все активные заказы и контролировать их прохождение по этапам доставки.

## MVP Features

- Создание нового заказа.
- Отображение заказов карточками на Kanban board.
- Четыре статуса: `Новый`, `Готовится`, `В доставке`, `Доставлен`.
- Перемещение заказа между этапами.
- Карточка показывает автоматически сгенерированный уникальный ID заказа, имя клиента, адрес доставки, краткую информацию о заказе и текущий статус.

## Acceptance Criteria

### AC1 — Создание заказа

- Обязательные поля: имя клиента, адрес доставки и краткая информация о заказе.
- Если обязательные поля заполнены корректно, заказ создаётся.
- Система автоматически присваивает заказу уникальный ID.
- Новый заказ всегда создаётся со статусом `Новый`.
- После создания карточка появляется в колонке `Новый`.
- Если обязательное поле пустое, заказ не создаётся.
- Пользователь видит понятное сообщение о незаполненном поле.

### AC2 — Kanban board

- Пользователь видит четыре колонки: `Новый`, `Готовится`, `В доставке`, `Доставлен`.
- Каждый заказ находится только в одной колонке, соответствующей его текущему статусу.
- После перезагрузки страницы сохранённые заказы остаются в актуальных колонках.

### AC3 — Перемещение заказа

- Заказ можно переместить между любыми из четырёх колонок.
- После перемещения статус меняется на статус новой колонки.
- Карточка исчезает из старой колонки и появляется в новой.
- После перезагрузки новый статус сохраняется.
- Ограничения допустимых переходов между статусами не входят в MVP.

### AC4 — Карточка заказа

Карточка обязательно показывает:

- ID заказа;
- имя клиента;
- адрес доставки;
- краткую информацию о заказе;
- текущий статус.

Данные разных заказов не должны смешиваться.

## Non-Goals

- Приложение для клиента.
- Приложение для курьера.
- GPS tracking.
- Маршрутизация и оптимизация маршрутов.
- Онлайн-оплата.
- Автоматическое назначение курьера.
- Уведомления клиенту.
- Сложные роли и permissions.
- Расширенная аналитика.
- Возвраты/refunds.
- Интеграции со сторонними delivery services.
